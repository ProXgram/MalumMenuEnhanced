# NavigationRouter offline regression checks

`NavigationRouter.Tests.csproj` links the actual navigation helper and planner into .NET 10 with local Unity/game stubs. **53/53 tests pass.** No native game, Unity, BepInEx or networking library is executed by the harness.

The tests simulate movement all the way to a nearby destination and around a wall; validate every planned segment through an open doorway; reject closed doors, thin walls and diagonal corner cutting; exercise a 6000-expanded-node unreachable search; and verify per-search occupancy/undirected-edge caching. Additional cases exercise cached nearby moving goals, dynamic obstacle invalidation, 0.75-second retry throttling, destination/map changes, invalid coordinates, synthetic physics failures and Reset.

Moving-target regressions exercise incremental search completion, a maximum of 32 newly expanded nodes and 128 physics predicates per search step, and at most 155 overlap/sweep calls per runtime tick including live route validation in the supplied fixtures. They walk a completed detour, retain a safe cached route while a changed goal waits or replans, finish searches despite changing target samples, throttle unreachable retries from completion, and reject newly blocked targets/segments, changed invalid body geometry and nonfinite clocks. Pending work remains observable past a five-second caller clock advance and clears on bounded failure/reset. Search also yields cooperatively after two milliseconds; a single native physics call cannot be interrupted. The tests do not measure native game frame times.

Completed-failure regressions distinguish an unreachable endpoint from a historical path whose exit closes before its live join. Both stop safely and expose a per-call MovingRouteFailed signal, which clears on subsequent cooldown/direct calls or Reset. A failed replacement search keeps a usable older segment without that signal. The optional failure trace is checked for outcome, actual search endpoint, work counts and geometry-reset information; it does not add physics probes or inspect player names/chat.

Frame-drift regressions use collider-center offsets observed separately in Skeld practice: (0, 0.1091), (-0.0217, 0.1078) and (-0.0041, 0.131), with unchanged radius. Small translations retain pending/cached work while live checks use the current center; substantial jumps still discard previous clearance. The fixture follows a continuously moving target 30-40 metres away through two doorways with both 0.06 and 0.24 proposed steps, bounded by the returned SteeringDistance, and verifies every actual step. Other cases rejoin a route around a Storage-style crate using an earlier visible point, validate recovery metadata and prevent fast-step oscillation around intermediate waypoints. These are synthetic navigation scenarios, not multiplayer gameplay or full controller integration.

Synthetic collision uses circles against rectangles and a conservative expanded-rectangle sweep. Added regressions measure native-style circle radius/world scale, bounding-box corners for other shapes, bounds-center offset, collider-layer collision masks, conditional ShortObjects, trigger filtering, radius invalidation and unavailable bounds. Contact-start recovery is tested against a reachable outward exit, opposing contacts, a new intervening obstacle, deeply embedded starts and already-clear ground. The fixture proves selection of the supplied masks/matrix; it does not prove the installed game's actual collision settings.

```powershell
dotnet run --project .\tests\NavigationRouter.Tests\NavigationRouter.Tests.csproj -c Release
dotnet build .\tests\NavigationRouter.Tests\sdk-check\SdkCheck.csproj -c Release
```

The separate SDK compile check links the same helper against AmongUs.GameLibs.Steam `2026.9.29` / .NET 6 and verifies the real collider geometry, collision mask, filtered overlap/circle-cast, reusable native array, ship-pointer and clock APIs compile. Installed interop metadata was also read without executing it to confirm relevant Physics2D signatures. It does not load or run the game. Its output remains under this test folder and is not installed.

Public API is `Direction(from, to, out status)`, `DirectionToMovingTarget(from, to, out status)`, `IsMovingRoutePending`, `MovingRouteFailed`, `SteeringDistance`, `IsRecovering`, `Reset()`, `CanStand(point)`, `CanTravel(from, to)` and `RecoverDirection(from, out status)`. Diagnostic getters are `Diagnostics`, `LastFailure`, `GeometryStatus`, `LastNativeException` and cumulative `GeometryResetCount`; the optional `FailureTrace` callback records completed failed searches at most once per second, with exceptions isolated from movement decisions. No names/chat or extra physics probes are recorded. Static/AI Direction keeps its existing synchronous planner. Moving-target Direction builds searches over multiple main-thread calls, holds each pending search goal until completion, and can continue a cached route only while its current movement segment passes fresh native checks. Completed paths try at most six live-checked join points rather than relying on the closest point across an obstacle. Callers can use IsMovingRoutePending to distinguish ongoing planning from a completed unreachable result when applying their own bounded wait timeout. MovingRouteFailed is true only for the latest DirectionToMovingTarget call when its search completed with no path or no reachable join and no usable retained movement; callers may then try another explicit floor goal. It is false during pending work, cooldown, direct movement and safe retained movement, and clears at the next Direction call or Reset. SteeringDistance describes the currently returned direct/waypoint/recovery segment and is zero for blocked/pending movement; callers cap their proposed step to this distance and validate ordinary steps with CanTravel. IsRecovering marks only the separately sampled outward exit, whose starting clearance contact causes ordinary CanTravel to reject it. Directions have unit magnitude or zero. For an owned native collider, clearance uses scaled circle radius (or bounding-box circumscribed radius for another shape) plus 0.025, with 0.16 minimum; queries apply bounds.center minus GetTruePosition offset. Solid queries intersect the collider's native collision matrix with ShipAndAllObjectsMask and ignore triggers. Per-frame offset jumps above 0.10 metres reset routing; smaller drift refreshes current geometry without restarting work. Collider identity, mask and radius changes still invalidate it. Reusable one-hit arrays avoid per-grid-query result allocations. Recovery probes at most 0.6 distance away from existing contacts, rejects new solid contacts and never writes a transform. Cells are 0.4; search is bounded at 6000 expanded nodes and twelve metres beyond the endpoint bounding box. Coordinates outside +/-2048 or trips exceeding 160 metres are rejected before physics/search allocation. Goals must be walkable; console approach sampling belongs to the AI task caller.

Native geometry was observed separately in Skeld practice on installed 3.3.16; this harness does not establish native map clearance, recovery behavior, layer configuration, ladders/platform transitions, cast performance or multiplayer results. The planner can return no route when its bounded search does not find one; no reachability promise applies to every map configuration. Caller gameplay/pause/ownership, measured-progress checks, braking and actual input delivery are outside this harness.
